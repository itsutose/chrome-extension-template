# Issue 011: Tailwind CSS移行作業

## 概要
Chrome拡張機能のスタイリングを従来のCSSからTailwind CSSに移行し、開発効率の向上とバンドルサイズの最適化を図る。

## 背景・課題
### 現状の問題
- バンドルサイズが3MB超と大きい（content.js）
- CSSファイルの管理が複雑
- スタイルの重複や一貫性の課題
- レスポンシブ対応の困難さ

### 解決したい課題
- バンドルサイズの大幅削減
- 開発効率の向上
- スタイル管理の簡素化
- デザインシステムの一貫性確保

## 技術要件

### 対応ブラウザ・環境
- Chrome Extension Manifest V3
- TypeScript + React
- Vite ビルドシステム

### 制約事項
- **CSP (Content Security Policy)** 対応必須
- 既存機能の動作保証
- 段階的移行によるリスク最小化

## 実装計画

### Phase 1: 基盤整備
- [ ] Tailwind CSSのインストール
- [ ] Vite設定の更新（PostCSS、PurgeCSS）
- [ ] Tailwind設定ファイルの作成
- [ ] CSP設定の確認・調整

### Phase 2: 簡単なコンポーネントから移行
- [ ] popup.tsxの移行（最もリスクが低い）
- [ ] 共通コンポーネントの移行
- [ ] 動作確認・テスト

### Phase 3: 複雑なコンポーネントの移行
- [ ] memo.tsxの移行
- [ ] content.tsxの動的UI部分
- [ ] レスポンシブ対応

### Phase 4: 最適化・検証
- [ ] PurgeCSSによる未使用スタイル削除
- [ ] バンドルサイズの測定・改善
- [ ] パフォーマンステスト
- [ ] ブラウザ互換性テスト

## 対象ファイル

### 移行対象
```
src/
├── core/
│   ├── popup.tsx          # 優先度: 高（最もシンプル）
│   └── content.tsx        # 優先度: 中（動的UI）
├── features/memo/
│   └── memo.tsx           # 優先度: 中（コンポーネント化済み）
└── shared/styles/
    └── memo.css           # 削除予定
```

### 設定ファイル
```
├── tailwind.config.js     # 新規作成
├── vite.config.ts         # 更新
├── public/manifest.json   # CSP設定更新
└── package.json           # 依存関係追加
```

## リスク・対策

### 主要リスク
1. **CSP制限による動作不良**
   - 対策: 段階的移行と各段階での動作確認

2. **ビルド設定の複雑化**
   - 対策: 設定ファイルの詳細なドキュメント化

3. **既存CSSとの競合**
   - 対策: 段階的削除とバックアップ戦略
